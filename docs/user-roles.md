# 部署者操作：普通用户与高级用户

本文件供接收源码并部署网站的人使用。角色只在后台数据库设置；前端包括高级账户也没有修改角色的功能。不要公开服务器终端或 Cloudflare 管理权限。

## 1. 权限规则

- **普通用户 `standard`**：新建账户及迁移后的旧账户均为此角色。可标注、查看自己的数量/统计/导出，也可浏览他人的标注图；他人数量、目录序号、批量目录导出、他人及全体统计不提供。
- **高级用户 `advanced`**：可查看所有参与者数量，以及我的目录、当前浏览目录和全体统计；可导出对应统计与目录。查看他人目录仍是只读，要修改需明确选择该账户；高级角色本身不增加跨账户写入权限。
- 所有人均可看参与者名单。名单中不公开密码及其散列。
- 所有用户名均可免密码选择，**高级账户登入后也先是普通权限**。只有点击「启用高级功能」并输入该账户的专用密码，当前会话才获得高级权限。前端只能验证密码，不能设置密码或角色。

## 2. 先应用数据库迁移

本次新增迁移：`drizzle/0002_profile_roles.sql`，给 profiles 加 `role`（默认 standard）、`access_code_hash`，给会话加专用密码验证字段。不修改原有椭圆或用户名。

### 本地安装或升级

```sh
npm ci
npm run dev:local
```

启动脚本按迁移记录自动应用未执行的 SQL；即使本地服务已在运行，也会检查迁移。升级后刷新网页。保留 `.wrangler/` 和 `.sites-runtime/local-migrations.json`，不要仅删除其中之一。迁移前可先停止服务并完整备份二者。

### 线上 Cloudflare Workers + D1

当前工程依赖 Cloudflare Workers + D1，不能只上传静态文件到 GitHub Pages。部署者需自行完成域名、Worker 和 D1 绑定，将真实数据库绑定到 **`DB`**。构建生成的 `dist/server/wrangler.json` 中本地占位数据库 ID 不是线上数据库 ID，不能直接拿来操作线上。

后台工具的 `--remote` 强制要求 `--config`，指向部署者维护的真实 Worker 配置（JSON/JSONC/TOML 均可），其中有真实 `d1_databases`、`binding: "DB"`、`database_name`、`database_id`。若使用 Worker 环境配置，请提供包含目标数据库的独立配置，避免误操作其他环境。操作账号需具备目标 D1 读写权限。

对已经运行本项目的线上数据库，先备份，再确认 0000、0001 已执行，只执行新增的 0002 一次：

```sh
npx wrangler d1 execute DB --remote --config /absolute/path/wrangler.production.jsonc --file drizzle/0002_profile_roles.sql
```

全新数据库按顺序执行 `0000_normal_sir_ram.sql`、`0001_wise_microbe.sql`、`0002_profile_roles.sql`。迁移文件不可重复执行，已存在字段时报错时先核对部署者的迁移记录，不要删除数据库来解决。线上与本地数据库独立，**本地授权不会自动授权线上用户**。

## 3. 让参与者先建立用户名

先让参与者在目标网站创建用户名。再在部署后台列出 ID：

```sh
# 本地数据库
npm run users -- list --local

# 线上数据库，路径替换成部署者的真实配置
npm run users -- list --remote --config /absolute/path/wrangler.production.jsonc
```

输出 `id`、`name`、`role`、`created_at`。请核对姓名并复制稳定的用户 ID。用 ID 授权，用户改名后权限仍属于原账户。不要按显示名字猜测或创建第二个同名账户。前端创建新账户始终是普通用户，请求中传 role 等字段也不会授权。

## 4. 指定某人为高级用户

将 `USER_ID` 替换成上一步查到的真实 ID，不要使用用户名：

```sh
# 本地
npm run users -- set --local --id USER_ID --role advanced

# 线上
npm run users -- set --remote --config /absolute/path/wrangler.production.jsonc --id USER_ID --role advanced
```

工具在后台终端提示输入该账户的专用密码两次，输入内容不会显示。密码为 **8–128 个字符**，由部署者决定，并私下告知对应高级用户。每个高级用户单独设置，不使用全站通用密码。

密码不通过命令行参数传入、不写入源码或公开日志；数据库只保存带随机盐的 PBKDF2-SHA256 派生结果（100,000 次迭代）。数据库字段名为 `access_code_hash`，现在存储的是加盐密码散列，不是明文或简单 SHA-256。

设置后该账户旧会话失效。用户重新免密码选择名字，仍只能使用普通功能；再点击顶部锁图标「启用高级功能」，输入专用密码后才能看到所有人的数量和全部统计范围。点击「高级功能已启用」状态按钮可退出高级功能。切换到任意用户名（包括再次选择自己）会恢复普通权限，需重新验证。已验证的同一会话可跨刷新保留，最长沿用 30 天会话期限。

自动化运维可使用 `--password-stdin` 从受保护的标准输入读取密码；不要把密码作为参数、写入共享 shell 历史或公开 CI 日志。交互式部署请直接用以上命令，不需这个参数。

需要设置多人时对每个 ID 分别运行一次，每个高级账户设置自己的专用密码。工具只修改指定 ID，不会自动把其他账户升级。

## 5. 降级、重置密码与改名

降为普通用户：

```sh
npm run users -- set --local --id USER_ID --role standard
# 或在线上
npm run users -- set --remote --config /absolute/path/wrangler.production.jsonc --id USER_ID --role standard
```

降级清空专用密码散列并清理该用户会话，保留用户名和全部标注。重新选择后是普通用户。若只是忘记/泄露密码，再执行同一条 `--role advanced` 命令，重新输入新密码两次，旧密码和旧会话失效，不会清空标注。

高级用户重命名保留 ID、角色和专用密码。删除高级账户会删除它的全部标注和会话；重新创建的同名账户有新 ID，默认为普通用户，须重新后台授权。

## 6. 发布前验收

1. 未登录：名单没有任何气泡数量，所有人的标注图可浏览，统计接口要求选择账户。
2. 选择普通用户 A：可见 A 的数量与统计；点击 B 浏览时，B 的总数、结果数和序号隐藏，无他人目录批量导出。统计窗口固定提供「我的目录」（仍为 A）。
3. 普通会话直接请求 `/api/statistics?scope=all` 或他人 profile 的统计返回 403；传 role 等字段到用户接口返回 403。
4. 免密码选择高级用户名：仍为普通权限；点击「启用高级功能」，未输入或密码错误不能启用，原会话不变。没有前端角色/密码设置入口。
5. 输入正确专用密码：名单显示各人的数量，统计可选我的目录、当前目录和所有参与者。切换用户名或点击退出高级功能后恢复普通权限。
6. 后台降级或重置密码：旧会话下一次请求即失效。刷新后需重新选择，旧密码不能再次启用高级功能。高级账户未验证时不能重命名或删除，验证后可管理本账户。

本地自动验证：先运行网站，再运行 `npm test`、`npm run test:api`、`npm run test:roles`。接口测试仅允许回环地址，建立并清理测试账户，不授权或删除真实参与者。

## 7. 数据可见性的实际边界

这些权限限制网站直接展示的数量、统计入口和统计接口。因为普通用户被允许看完整的他人椭圆图，浏览器必须接收相关记录，无法阻止自行数图或分析地图 API。普通账户还延续免密码且可自由切换的设计，切换成另一普通账户后可查看该账户自己的统计；若需防止此类冒用，应另行为普通账户也加入身份验证。

高级账户不能仅靠点击名字取得高级权限，必须再验证专用密码。后台角色设置不会使先前已经下载的图表、浏览器页面或已获知的数据消失；撤权控制后续请求。

项目仍为本地开发版本。本文件说明部署者将来怎样配置，不表示网站已经上线。
